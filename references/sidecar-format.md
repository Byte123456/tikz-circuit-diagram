# 侧车格式与连通规则

只在**要改检查器**或写新宏时才需要读这一页。写图读 `quickref.md` 就够。

## 为什么是侧车，而不是解析 SVG

从渲染产物里反推几何是**做不到可靠**的：要先剔除元件分组、过滤装饰线、只认
正交线段，还要专门处理"坐标不是数字的畸形 `<line>`"——任何一步漏了，检查器就
在对着错误的几何下判断。

本方案绕开整件事：图由 TeX 排版时，"检查器反推几何"变成"检查器读画图时顺手
写下的日志"。`\Wire{a}{b}` 把两端解析成 pt 坐标**一次**，然后用**同一组坐标**
既画线又写日志——所以图与日志**不可能脱节**，这是结构性保证。

**不要**试图改成"渲染成 SVG 再解析"：实测 `dvisvgm`/`pdftocairo` 的产物里没有
`<line>/<rect>/<circle>`，只有 `<path>` + `transform="matrix(...)"`（要把点算回
`(a*x+c*y+e, b*x+d*y+f)`，等于重写解析器）；而且同一个 `.xdv`，
`dvisvgm --no-fonts` 出 2 条 path、换 `--font-format=woff2` 后出 **0** 条——
电路几何整体消失。

## 记录类型

每行一条，字段用 `|` 分隔，**坐标单位 pt**（`parse_sidecar` 的 `_num()` 会剥掉
可能的 `pt` 后缀）。

| 记号 | 格式 | 含义 |
|---|---|---|
| `W` | `W\|x1\|y1\|x2\|y2` | 导线线段 |
| `WH` / `WV` | 同上 | 同上，且**声明**它是水平/竖直的（斜了会被报出来） |
| `J` | `J\|x\|y` | 结点。交叉处要连通就得画它 |
| `T` | `T\|元件名.端子名\|x\|y` | 元件端子 |
| `B` | `B\|元件名\|x0\|y0\|x1\|y1` | 元件**本体**实心盒（不含标签/引线） |
| `GS` | `GS\|网络名\|x0\|y0\|x1\|y1` | 电源/地**符号的图形范围**（排版障碍物） |
| `P` | `P\|网络名\|x\|y` | 电源/地符号的**连接点** |
| `G` | `G\|标签号\|x\|y` | 网络标签（同号相连） |
| `E` | `E\|元件名.端子名\|目标` | 期望：该端子应与"目标"同网 |
| `X` | `X\|序号\|类型\|x0\|y0\|x1\|y1\|文字` | 标注/值标签的**真实排版盒** |
| `A` | `A\|键\|序号\|锚点x\|锚点y\|角次序\|样式\|参考点\|x0\|y0\|x1\|y1\|文字` | `\AnnoAt` 记录（`place.py` 的输入） |
| `N` | `N\|生成坐标名\|...` | `\ShowNames` 的产物（检查器忽略） |
| `M` | `M\|...` | **记账警告**（零长导线、找不到 label 节点） |
| `C` | `C\|x0\|y0\|x1\|y1` | 画布范围（由 `\DumpCanvas` 登记） |
| `#` | `#...` | 注释/统计，检查器忽略 |

`X` 的第 2 个字段（类型）取 `R`（`\Anno` 显式登记）或 `L`（`\LogLabel` 值标签）
或 `A`（`ann` 样式的自动兜底登记）。回归测试靠它区分"有几个值标签"。

### `GS` 与 `P` 为什么是两条记录

`P` 只记一个**连接点**——它参与连通性（同名自动同网）。
`GS` 记符号的**图形范围**——它是**排版障碍物**，不参与连通性。

分成两条是因为"文字压在接地符号上"这类问题，**拿一个点和文字盒比永远比不出
重叠**。这是开发时**目视**发现的一个盲区（两道门都报 0，因为检查器手里只有
一个点）：`\cGND` 的横杠落在标注文字中间，任何几何检查都看不见。

### `A` 记录的两个用途

`place.py` 从 `A` 记录拿到：**锚点坐标** + **当前文字盒**。
由这两者可反推文字尺寸——所以**不需要单独记一次尺寸**。

第一遍编译时偏移全为 0，盒中心正好落在锚点上，宽高照样精确。

## 连通规则

**端点相接才算连通；中途交叉不算**——除非交点处登记了结点 `J`。
容差见 `sidecar.TOL`（0.8pt）。

这条规则**决定成败，不要去改**：少了后半句，两条只是视觉上交叉的导线会被判
成连通，报出一堆"分压网络短路"的假阳性，比不查还糟。

三个推论：

1. **斜线整个丢弃**（`is_orthogonal` 为假）。丢弃 = 漏检，所以 `\WireH`/`\WireV`
   会写 H/V **意图**记录，由 Python 判定并报错（不在 TeX 里判定——见下）。
2. **端子直接对接算连通**（两个 `T` 坐标重合，中间没有 `W`）。`\Chain` 把元件
   串在一条路径上，相邻元件就是端子对端子直接对接，侧车里**没有**对应的 `W`
   记录——这不是缺口。
3. **零长线被过滤**（`is_degenerate`），但 TeX 侧已经把它记成 `M|` 报出来了。
   两边都要有：过滤是为了不让它污染连通性，记账是为了不让它静默消失。
   **早先只有前者**，于是"电气门过滤掉、没人报"，两个门的导线计数还对不上。

## 为什么正交判定在 Python 而不在 TeX

试过在 TeX 里用 `\ifdim` 判"两端 y 是否相同"，**不可靠**：
`\wax`/`\wbx` 由 `\pgfgetlastxy` 定义（展开成 `"91.04869pt"` 这样的**宏**），
把两个这样的值放进 dimen 寄存器再用 `\ifdim` 比，行为不稳定——实测同一个值
既走进"超阈"分支又打印出差值 `0.00003pt`，`\sndiff=-\sndiff` 取负也静默失效。
TeX 的 dimen 算术对"寄存器 vs 展开宏"两套取值路径不做统一处理。

Python 里算一遍过、可写回归测试，报错时还能给出两端完整坐标。

同类坑还有一处：`\LogLabel` 判零面积盒**必须用 `\pgfmathparse`，不能用 `\ifdim`
比 `\pgfgetlastxy` 的结果**——连续调用会静默失效（实测三次同构调用只成功一次），
后果是值标签全部没进侧车而门禁报 0 问题。对照实验：

| 实现 | 三次调用成功率 |
|---|---|
| `\ifdim` + `\dimen0`/`\dimen2` | 1/3 |
| `\ifdim` + `\newdimen` 私有寄存器 | 1/3（换寄存器救不了） |
| `\pgfmathparse` | **3/3** |

回归里有 `\LogLabel` 的 3/3 断言护着这条。

## 两条门的分工

| | 排版门 `check_tex_layout.py` | 电气门 `check_tex_net.py` |
|---|---|---|
| 数据 | `W`/`B`/`GS`/`X` | `W`/`T`/`B`/`P`/`G`/`E`/`M` |
| 判据 | 几何重叠/间距/越界 | 并查集连通性 |
| 检查项 | 七类 | 九类 + 记账警告 + 空侧车 |
| 退出码 | 0 干净 / 1 有问题 / **2 没检查成** | 0 干净 / 1 有问题 / **2 没检查成** |

**`rc=2` 与 `rc=1` 必须分清**：1 是"查过了，有问题"；2 是"**根本没查成**"
（侧车不存在、空文件、用法错）。两者都非 0，但含义相反 —— 把 2 说成"电路
有问题"会让人去改本来没错的电路。空侧车还会在报告里打 `[空侧车]`：侧车里
没有任何电气实体时，它**不是"电路干净"，是"没检查到东西"**。这正是本项目
最危险的失效模式 —— "查了没问题"和"压根没看"在输出上长得一模一样。

**容差只有一个数**（`sidecar.TOL = 0.8pt`）：两个点对接、端点落在线上、
悬空判定**全部用它**。此前三处各用 0.8/1.2/量化 key，于是相差 0.5pt 的两个
点会落进"网表判分离、悬空却不报"的矛盾区 —— 用户不知道信哪个。相差
`>TOL` 但 `<=NEAR_TOL(2.0)` 的点对**不算连通**，但会报 `[近接]`（实测真图
里合法接触非精确重合即相距很远，没有"差一点点"的合法情况）。

**两道是独立的**：排版干净不证明电路对；电路对不证明摆得整齐。

而且**"两道门都报 0"也不证明"画的就是你要的那个电路"**——两道门查的都是
**图自身**的自洽性（摆得整不整齐、连得对不对），它们没有"应该长什么样"的
参照物。要证明"这张图和设计意图一致"，得用 `--show-nets` 把网表打出来
**逐网人工核对**（器件落在哪张网、极性方向对不对）。**这是交付前的最后一步，
没有工具能替代。**

# 以下是**改 style / 改检查器**时才需要的内容

画图用不到这些。放在这里是为了防止有人"顺手优化"掉它们所保护的东西。

## TeX 侧尺寸算术的四个陷阱

改 `stm32tikz.sty` 或写新宏时才会遇到：

- `\dimexpr` 里**不能有括号**：`(\n-1)*\pitch` 报 `Illegal unit of measure`。
  写成纯乘除加减：`\dimexpr \pitch*\n/2 - \pitch/2 \relax`。
- **`0.5\dimen寄存器` 不成立**（"数字直接贴寄存器"），要 `/2` 或 `*5/10`。
- **`\foreach` 的循环体是有分组的**，计数要用 `\global\advance`——普通
  `\advance` 循环结束后回退。症状很隐蔽：**间距是对的，但整体偏了一个间距**
  （因为 n 当 0 用了，居中项少了一半）。这与 `\Chain` 里"循环变量局部化、
  要 `\xdef` 存末项"是同一类坑。
- **`\pgfgetlastxy` 用 `\edef` 把参数定义成宏**，所以 `\SNresolveTo` 的输出
  参数必须是**宏名**，不能传 dimen 寄存器（传了会被 `\edef` 成宏）。
- **参数个数变了，位置引用要一起查**。`\MCUauto` 初版省掉"高"却忘了改
  `#5/2`，于是说明文字被当成尺寸喂给 pgfmath，报
  `Unknown function 'STM32F103C8T6'`——报错完全不指向真因。

另一类**不是坑但必须定对**的：`\MCUauto` 初版的引脚顺序是**自下而上**的
（列表第一个在最下面）。间距一样匀，图上"看不出错"，任何门禁也查不出；
但引脚号与数据手册相反，读数手册的人会看错。这类"语义反了"只能靠**定对
方向**来防，所以回归里有一条专门断言"列表第一个必须在最上面"。

## `TEXINPUTS` 的顺序 —— 会让 `\input` 静默读到**错的文件**

出图通路固定是 `xelatex → PDF → pdftocairo -svg`（理由见本文开头）。
这里记一个与它相关、**踩过并且很隐蔽**的坑：`_paths.texinputs_env()` 往
`TEXINPUTS` 里加技能目录时的**位置**。

初版写的是 `技能目录;原值;` —— 技能目录**排在最前**。于是 xelatex 优先在
技能目录里找**任何** `\input` 的文件。技能目录下恰好有一份 `auto_offsets.tex`
（开发时的残留），结果在**别的目录**编译时，`\InputAnnoOffsets{auto_offsets.tex}`
读到的是技能目录那一份，刚生成的那份被忽略。症状：

* 偏移**算对了**（`auto_offsets.tex` 里 `snao*` 都在），但图上没生效；
* **编译不报任何错** —— 因为它读到了一个合法文件。

正确写法是 `原值;技能目录;`：用户工程（含 cwd）优先，技能目录只兜底。
末尾那个分号也**必须**有，它的含义是"再加上默认搜索路径（含当前工作目录）"，
少了它 cwd 里的文件会找不到。

同理，**回归用例里的探测文档与偏移文件要用独一无二的名字**
（`sn_probe_<tmp名>.tex`），不要用 `probe.tex` / `auto_offsets.tex` 这种通用名 ——
否则会被 cwd 里的同名文件遮蔽，而失败表现是"用例偶发失败"，极难查。

## "门禁报 0 却其实没查"的盲区

本工具的检查能力**没有一次是靠调阈值补上的**，都是"换个角度看图"发现的。
记在这里，是因为每个都对应一条现在看起来"多余"的检查或记录：

| 盲区 | 根因 | 现在的对策 |
|---|---|---|
| 文字压在器件本体框线上 | 只比了"文字↔文字"和"文字↔导线"，没有"文字↔器件" | 排版门第 6 类（判据是**文字盒中心落在本体盒内**，不是两盒相交） |
| 文字压在接地符号上 | `\Power` 只记**一个连接点**，拿点跟文字盒比永远比不出重叠 | `GS\|` 记录符号图形范围 + 排版门第 7 类 |
| 零长导线静默穿过 | 电气门**过滤**掉退化线，却没人报"它被过滤了" | `\Wire` 记 `M\|` 警告；电气门**开始读** `M\|` |
| 值标签全部没进侧车 | `\LogLabel` 的 `\ifdim` 连续调用静默失效 | 改用 `\pgfmathparse` + 端到端回归断言 |
| 空侧车/侧车不存在当"干净" | 检查器对不存在的文件"跳过"、对空侧车"无问题可报"，都返回 0 | 缺失/空文件返回 **2**；空侧车打 `[空侧车]` |
| 同名端子/本体盒被静默覆盖 | 解析时后一条覆盖前一条，先出现的信息消失 | 解析时比对坐标，异坐标报 `[重名]`（同坐标不报，那是良性的） |
| 悬空判定与网表用两套容差 | 网表 0.8pt、悬空 1.2pt，同两点给出**矛盾**结论 | 统一走 `TOL`；中间地带报 `[近接]` 而不放宽容差 |
| `build.py` 掩盖阶段失败 | place/pdftocairo 失败也返回 0；pdftocairo **失败不退非 0** | 各阶段失败传播为 rc=2；SVG 以**产物是否存在**判定 |
| 跳过用例算作通过 | 缺 xelatex 时 9 个 TeX 用例 append 进 PASS，仍打印"全部通过" | 分 PASS/FAIL/SKIP 统计，有 skip 即退出码 1 |

共同点值得记住：**根因都不是阈值不对，而是"被检查的对象压根不在检查的
范围内"**（或"结论没人看"）。所以"查了没问题"和"压根没看"在输出上长得
一模一样——这是这套工具最需要持续警惕的失效模式。

推论（已写进 SKILL.md）：改检查器之后必跑回归；新增检查时先写一个能复现的
注错用例并确认它 **FAIL**，再去修。
